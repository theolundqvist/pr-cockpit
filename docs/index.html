Webhook-aware. Locally cached.

A marker for a cached PR triggers a targeted refresh; repo-level markers fall back to a debounced poll. The open PR view checks local state every 12 seconds; the review queue every 30 seconds. Your own comments, reviews, and merges appear immediately while PR Cockpit writes them back to GitHub.

One key from review to change.

Edit where you read.

Press e on the open PR and the full file opens at the changed line under your pointer — or right-click a line for Edit here. Leaving the editor shows your patch as a diff with a commit message. Commit to PR writes it to the PR head.

One task, one agent.

Press p and describe one task. PR Cockpit launches a one-shot agent in a dedicated PR workspace, where it can do the work, commit, and push to the PR head.

Roll back one hunk.

Right-click inside a hunk and choose Revert hunk. PR Cockpit verifies the hunk still matches the current file, builds the inverse change, and opens it for review with a prefilled message. Nothing is pushed until you choose Commit to PR.

  1. 1Right-click → Revert hunk
  2. 2Review the inverse diff
  3. 3Commit to PR

Trace the file. Or the symbol.

Press h on a file to walk this PR and up to 30 earlier commits — author, a PR or commit link when known, and available diffs — without leaving the review. Right-click a symbol in search for the commits that mention it.

Agents wait. The webhook wakes them.

pr-cockpit listen fixture/cockpit#101 blocks on the cached PR. A substantive review update triggers a targeted refresh, changes the local fingerprint, prints the refreshed PR, and exits — without repeatedly polling GitHub.

A local copy GitHub keeps fresh.

GitHub stays the source of truth. A marker for a cached PR triggers a targeted refresh; repo-level markers fall back to a debounced poll. The app paints cached PRs, local search results, and warmed diffs from SQLite and disk, while cold or extended lookups fetch GitHub and populate the cache. Comments, reviews, and merges paint immediately while PR Cockpit writes them back to GitHub, with visible pending and retry states.
